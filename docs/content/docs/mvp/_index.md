## MVP Purpose

Test whether intent-first, consented introductions create useful next actions for a defined audience.

## Primary User and Buyer

- **Primary user:** a participant with a specific collaboration need.
- **Primary buyer:** an organization operating a network, program, or opportunity pipeline.

## Must-Have Workflow

1. A participant creates an intent record.
2. An operator or system identifies a plausible collision.
3. Both parties review a concise collision brief.
4. Reciprocal interest opens an airlock.
5. Consent releases only the agreed identity and introduction.
6. An outcome is recorded.

## Must-Have Features

- Intent creation and editing
- Collision brief generation
- Reciprocal interest states
- Consent and identity release
- Operator review queue
- Outcome capture

## Participant Experience

Simple, specific, and permissioned. The participant should understand why a match is relevant before sharing identity.

## Operator Experience

A queue for reviewing intent quality, collisions, consent state, introductions, and outcomes.

## Manual vs Automated

Start with manual review and assisted matching. Automate only after the workflow and evidence standards are clear.

## Deferred Features

Broad discovery, reputation scoring, complex recommendation systems, and unattended automation are deferred.

## Success Metrics

Pilot targets should measure qualified collisions, reciprocal interest, consented introductions, completed meetings, defined next actions, Day 7 outcomes, and Day 21 outcomes. Baselines remain unresolved.
